Capítulo 1  |  Resumen Ejecutivo, Visión del Ecosistema y Stack Tecnológico

NGCourse es la plataforma de cursos en línea de NEXTGEN IA. Con una sola base de código sirve dos tipos de contenido, distinguidos por cursos.marca: cursos NEXTGEN, propios, que pueden ser gratuitos o venderse de forma individual con PayPal, y cursos RAM, capacitación interna de la empresa cliente, a los que se accede por la licencia que el administrador asigna a una organización o por una invitación. Cubre el ciclo completo: creación del curso (módulos, lecciones de video, lectura o quiz y recursos descargables), publicación, asignación a empresas o venta, inscripción, reproducción de video por Bunny Stream, quizzes calificados en el servidor, comentarios, reseñas y certificado PDF con folio verificable.

Los cursos pueden agruparse en cursos globales (en la interfaz, "procesos"): un curso tipo=global no tiene módulos propios y contiene cursos individuales ordenados por orden_en_padre; su licencia cubre a todos sus hijos. El navegador solo habla con el dominio del frontend: las llamadas a /api/v1/* pasan por el BFF de Next.js, que las reenvía al backend conservando las cookies HttpOnly, por lo que la app no necesita CORS en producción.

4.2 Autorización y Endurecimiento

  • Roles: AdminOrSuperuser (toda la plataforma), SupervisorOrAbove (su organización vía _get_user_org), instructor (solo sus cursos, rol congelado por el flag instructores) y alumno (sus inscripciones). Cada endpoint además valida propiedad del recurso.
  • Escalada de privilegios: UserUpdate con extra="forbid" y sin is_superuser; solo el superusuario modifica cuentas de administrador; nadie se suspende a sí mismo; el correo no se cambia.
  • Cabeceras: backend con CSP default-src 'none'; frontend con CSP por nonce, X-Frame-Options: DENY, nosniff y HSTS solo con ENABLE_HTTPS=true.
  • Archivos: portadas ≤ 5 MB, avatares ≤ 2 MB, recursos ≤ 20 MB, validados por magic bytes; certificados y recursos solo por endpoint autenticado.

5.2 Progreso, Certificados y Empresas

  • Progreso: el aula envía visto_seg y progreso_pct cada 10 s; la lección se completa al cruzar su umbral (90 %). Lecturas con 100 % al marcarlas; quiz al aprobar.
  • Certificado: check_and_emit_certificate emite folio NG-XXXXXXXXXXXX, hash de verificación y PDF (ReportLab) si todas las lecciones visibles están completas y el perfil tiene nombre real.
  • Cursos globales: no admiten inscripción directa; su licencia cubre a todos los subcursos ordenados por orden_en_padre.
  • Organizaciones: al quitar a un miembro se revocan las inscripciones que solo cubría la licencia de esa empresa; invitaciones válidas 7 días y de un solo uso.

6.1 Bootstrap y Convenciones (app/api/main.py)

api_router registra 21 routers siempre y private solo con ENVIRONMENT=local; todo cuelga de /api/v1. Los listados devuelven {data, count} con skip y limit; los errores son HTTPException con detail en español: 400 dato inválido, 401 sin sesión, 403 sin permiso, 404 no existe o no visible, 409 conflicto de estado, 429 rate limit, 502 PayPal/Bunny, 503 integración sin configurar. Las guardias que dependen del curso concreto viven en el cuerpo del endpoint: _require_curso_owner_or_admin, _tiene_acceso_contenido, _strip_leccion_sin_acceso y _sanitize_quiz_for_student.

5. POST /webhooks/bunny  Status 3/4 → hls_url, thumbnail_url, duracion_seg  ·  Status 5/6 → limpia para reintentar
Flujo de compra (PayPalCheckout.tsx → pagos.py → PayPal)
1. POST /pagos/crear-orden {curso_id}  → valida curso pagable, crea Pago(pendiente) y orden PayPal (MXN)
2. Botones de PayPal con el order_id; el alumno aprueba
3. POST /pagos/confirmar {pago_id, paypal_order_id} → capture_order(); COMPLETED → Pago(completado)
4. Se crea o reactiva la inscripción ACTIVA  ·  error de PayPal → Pago(fallido) y 502

0 · 1 · 2queued, processing, encodingSin cambios; el editor sigue consultando video-status.

6.5 Receta para Agregar un Endpoint

  • Modelo en app/models/<dominio>.py y migración con alembic revision --autogenerate (revisar siempre el archivo y dar server_default a columnas nuevas).
  • Esquemas XxxCreate / XxxUpdate / XxxPublic y lógica en crud.py.
  • Endpoint con la guardia adecuada: 404 si no existe, 403 sin permiso, 409 por estado; @limiter.limit y request: Request si es público.
  • Método en frontend/src/lib/api/client.ts, prueba en backend/tests/api/routes/ y fila en docs/06-backend-api/endpoints.md.

9.1 Secuencia de Arranque Local y Producción (Docker Compose)

Comandos de inicialización desde ngcourses/
1. Variables:            cp .env.example .env   (llenar SECRET_KEY, POSTGRES_*, FIRST_SUPERUSER…)
2. Stack local:          docker compose up -d   (db + prestart + backend :8000 + mailcatcher :1080)
3. Frontend:             npm install  &&  cd frontend  &&  BACKEND_URL=http://localhost:8000 npm run dev
4. Migraciones:          automáticas en prestart  (manual: docker compose exec backend alembic upgrade head)
5. Producción (EC2):     docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
6. Salud del backend:    docker exec ngcourses-backend-1 curl -s http://localhost:8000/api/v1/utils/health-check/

9.2 Variables de Entorno, CI/CD y Troubleshooting

  • Variables .env: .env.example / .env.prod.example (SECRET_KEY, POSTGRES_*, FIRST_SUPERUSER, RESEND_API_KEY o SMTP_*, BUNNY_*, PAYPAL_*, SENTRY_DSN, DOMAIN) y del frontend (BACKEND_URL, ENABLE_HTTPS, NEXT_PUBLIC_*).
  • CI/CD: ci.yml en cada PR (npm audit, tsc, build; uv sync --frozen, pip-audit, migraciones, pytest informativo). deploy.yml en cada push a main: git archive → scp a la EC2 → limpia todo salvo .env.prod → up -d --build. Secrets: EC2_HOST, EC2_USER, EC2_SSH_KEY. Traefik enruta app./ngcourse. → frontend y api. → backend.
  • Solución de Problemas: prestart fallido → docker compose logs prestart y alembic current; video "procesando" → revisar BUNNY_WEBHOOK_SECRET y la URL del webhook en api.; CSP rota → servir por HTTPS y mantener force-dynamic; "Token inválido" en cuentas viejas → reenviar activación; nunca correr pytest contra una BD con datos (conftest.py borra usuarios).
